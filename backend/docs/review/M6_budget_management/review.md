## P1 — 동시 갱신 시 사용자 예산 합계가 팀 한도를 초과할 수 있음

팀 한도가 100이고 사용자 예산이 아직 없다면, 서로 다른 사용자를 대상으로 하는 두 요청이
각각 한도 60을 동시에 설정할 수 있다. 두 요청은 모두 현재 배분 합계 0을 읽고, 각각의
예상 합계 60이 팀 한도 이하라고 판단한다. 이후 서로 다른 사용자 `budget_configs` 행을
삽입하므로 행 단위 충돌 없이 둘 다 커밋되어 최종 합계는 120이 된다.

같은 문제는 전체 교체 배분 API에도 있다. 두 요청이 빈 기존 배분을 읽고 각기 다른 멤버를
포함한 배분을 저장하면, 두 활성 사용자 예산이 함께 남을 수 있다.

영향은 배분 불변식(`사용자 예산 합계 ≤ 팀 예산`) 훼손이다. 팀 예산이 `SOFT_WARN`이면
개별 `HARD_BLOCK` 한도가 팀 한도보다 커진 상태가 실제 집행에도 영향을 준다.

관련 코드:

- `BudgetService.set_allocation()` — 팀 설정과 기존 배분을 잠금 없이 읽고 검증한다.
- `BudgetService._ensure_within_team_limit()` — 팀 설정과 전체 배분을 잠금 없이 읽고 검증한다.

권장 수정:

1. 팀 예산 설정 행을 `SELECT ... FOR UPDATE`로 먼저 잠가, 같은 팀의 사용자 예산 변경과
   배분 변경을 직렬화한다. 팀 예산이 없는 상태의 경쟁까지 막아야 한다면 팀 ID 기반 PostgreSQL
   advisory lock을 사용한다.
2. 팀 한도 변경, 사용자 단건 변경, 배분 전체 교체가 모두 같은 잠금 규약을 사용하게 한다.
3. 두 동시 요청의 최종 합계가 팀 한도를 넘지 않는 통합 테스트를 추가한다.

## P1 — 4자리 초과 금액이 재시드의 Redis와 DB 값을 다르게 만듦

예산 요청 모델은 금액에 음수 방지 규칙만 적용하고 소수 자릿수와 전체 자릿수는 제한하지
않는다. 반면 DB 열은 `numeric(14,4)`이다. `used_usd = 0.00005`를 재시드하면 PostgreSQL은
4자리 정밀도로 저장하지만, Redis 카운터 문자열은 Python `Decimal.quantize()`의 기본
`ROUND_HALF_EVEN` 규칙으로 `0.0000`이 된다.

검토 시 다음을 확인했다.

```text
BudgetSetRequest(limit_usd="0.00005") -> 0.00005
ReseedRequest(... used_usd="0.00005") -> 0.00005
counter_value(Decimal("0.00005")) -> "0.0000"
```

따라서 재시드 뒤 DB 내구 사본과 gateway가 집행에 사용하는 Redis 카운터가 달라질 수 있다.
같은 입력이 설정·배분·재시드에서도 DB 반올림과 서비스 계산을 다르게 만들 수 있다.

관련 코드:

- `BudgetSetRequest.limit_usd`, `AllocationItem.limit_usd`, `ReseedItem.used_usd`
- `BudgetUsage`와 `BudgetConfig`의 `numeric(14,4)` 열
- Redis 카운터 문자열을 만드는 `counter_value()`

권장 수정:

1. 모든 금액 입력에 `max_digits=14`, `decimal_places=4`를 적용해 DB 표현 범위를 벗어난
   요청을 422로 거절한다.
2. 필요한 경우 명시적인 반올림 규칙을 정하고 DB 저장값과 Redis 쓰기에 동일하게 적용한다.
3. 5번째 소수 자릿수, 전체 자릿수 초과, 경계값 재시드에 대한 API·DB 통합 테스트를 추가한다.

## P1 — Redis 쓰기 실패 후 재시드가 성공으로 완료되며 자동 복구되지 않음

재시드는 DB 변경과 감사 로그를 먼저 커밋한 후 Redis `SET`을 수행한다. Redis 쓰기가 실패하면
응답은 정상 HTTP 성공 응답이고 해당 항목만 `counter_updated: false`가 된다. 이 실패를 기록해
재시도하는 outbox나 background job은 없다.

그 결과 운영자가 응답의 항목별 상태를 놓치면 DB는 새 소진값을 갖지만 gateway는 옛 Redis
카운터로 예산을 집행한다. 이는 문서의 “Redis 카운터와 `budget_usages`를 함께 갱신”한다는
재시드 계약을 충족하지 못한다.

권장 수정:

1. Redis 동기화 실패를 내구적으로 기록하고 background job이 성공할 때까지 재시도하게 한다.
2. 재시드 결과가 부분 실패일 때 운영자가 즉시 조치할 수 있도록 명시적인 실패 상태와 경보를
   제공한다.
3. Redis 장애 뒤 복구 재시도와 최종 DB·Redis 일치 여부를 검증하는 통합 테스트를 추가한다.
